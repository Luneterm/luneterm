# Lunegit terminal bug ledger

Bugs and gaps found in Lunegit's terminal (as of 2026-10-29), and what Luneterm must do about each.
Paths refer to the Lunegit repo. Every fixed bug gets a regression test here too.

| # | Issue (Lunegit) | Status there | Luneterm |

| 1 | Wide glyphs spill onto the next cell | Fixed (glyph containment) | Fixed in `lune-termview` (M2): Lunegit's rule ported with its cases (`contain` unit tests, `fit_scale_lunegit_cases`, `allowance_cases`), plus a per-glyph clip rect in the shader and the font-independent `containment_no_spill` test (CJK, emoji, combining flood, box drawing) |
| 2 | Glyphs overflow vertically into adjacent rows | Open, by design | Fixed in `lune-termview` (M2): every glyph instance carries a clip rect whose vertical extent is its row, enforced in the fragment shader (decision D5); covered by `containment_no_spill` |

| 19 | Pasted text can end bracketed paste early (`ESC [ 201 ~` in the clipboard) and run the rest as typed input | Open (`PtyTerminalSession.cs:351-368` wraps the text, no sanitising) | Fixed by design in `lune-vt` (M7 step 6, plan D7, user decision Q22): `Terminal::paste` / `paste_bytes(text, bracketed)` (`input/paste.rs`). Both modes: `\r?\n` becomes `\r`. Bracketed only: every `ESC [ 200 ~` and `ESC [ 201 ~` is removed in one left-to-right pass, then every C0 control except HT and CR (so no ESC survives, even one reassembled from fragments) and every C1 control U+0080..=U+009F (an 8-bit CSI to programs that honour C1) is dropped, and the text is wrapped in the markers. Not bracketed there is no paste boundary to protect, so only the line-break rule applies. Tests: `bracketed_output_never_leaves_the_brackets` (40 seeds x 500 inputs over a hostile alphabet, with the output length bound), `a_pasted_end_marker_is_removed_and_the_rest_stays_inside_the_brackets`, `a_pasted_start_marker_is_removed_too`, `bracketed_output_is_idempotent_on_its_own_inner_text`, `paste_with_bracketed_mode_wraps_and_sanitizes`, `paste_queues_no_host_event_and_never_logs_the_text`. An empty paste sends nothing (Lunegit's `PasteAsync` skips it as well) |
